# ICBAR | GitHub Actions crawler + SQLite + standalone photo downloader

این پروژه **خودکار در GitHub Actions** دایرکتوری `https://icbar.ir/api/v1/directory/` را صفحه‌به‌صفحه بررسی و جزئیات هر `slug` را دریافت می‌کند. **تصاویر روی GitHub دانلود نمی‌شوند**؛ در عوض URL تک‌تک تصاویر در فایل `download_photos.sh` قرار می‌گیرد تا روی کامپیوتر شخصی دانلود شوند.

## شروع سریع

1. یک **ریپوی Private** در GitHub بساز؛ فایل‌های این پروژه را به **ریشه ریپو** منتقل و Commit کن (حتماً پوشه مخفی `.github/workflows/` هم باشد).
2. از تب **Actions**، workflow به نام **ICBAR - Incremental Archive** را باز کن؛ **Run workflow** را بزن و فیلدها را روی مقدار پیش‌فرض نگه دار.
3. Workflow با `contents: write` تغییرات خروجی را خودکار به **همان Branch** که اجرا شده Push می‌کند. اگر Branch protection اجازه Push نمی‌دهد، باید Branch دیگری را انتخاب کنی یا مجوز مربوط را تنظیم کنی.
4. پس از اتمام یا در طول اجرا، فایل‌های زیر در ریپو ایجاد می‌شوند:
   - `data/icbar.sqlite3.gz` — نسخه فشرده دیتابیس SQLite
   - `data/photos.tsv` — آدرس تمام تصاویر با شناسه و مسیر ذخیره
   - `data/summary.json` — آمار رکوردها و پیشرفت
   - `download_photos.sh` — **فایل Bash مستقل، شامل آدرس همه عکس‌های کشف‌شده**

## دانلود تصاویر روی سیستم

فایل `download_photos.sh` را از آخرین Commit دریافت کن. فقط `bash`، `curl` و `xargs` نیاز دارد (اختیاری: `file` برای تشخیص فایل‌های نامعتبر).

```bash
chmod +x download_photos.sh
./download_photos.sh --count            # تعداد آدرس‌های داخل خود فایل
./download_photos.sh --list | head      # نمایش نمونه آدرس‌ها
JOBS=6 ./download_photos.sh            # دانلود موازی در ./icbar_images/photos/...
```

تکرار اجرای این فایل عکس‌های **کامل دانلودشده** را رد می‌کند و تلاش می‌کند فایل‌های `.part` را ادامه دهد؛ اگر سرور HTTP Range نداشته باشد از ابتدا همان عکس را می‌گیرد. برای تغییر محل ذخیره:

```bash
OUTPUT_DIR="$HOME/Downloads/icbar" JOBS=4 ./download_photos.sh
```

> **مهم:** اسکریپت عکس‌ها مستقل از SQLite است، اما نسخه فایل عکس‌ها تنها آدرس‌هایی را دارد که تا آخرین Commit کشف شده‌اند. بعد از اجرای کامل کرالر جدیدترین `download_photos.sh` را بگیر.

## دیتابیس

دانلود `data/icbar.sqlite3.gz` از ریپو و استخراج:

```bash
gzip -dk icbar.sqlite3.gz
sqlite3 icbar.sqlite3 'SELECT COUNT(*) FROM profiles;'
sqlite3 icbar.sqlite3 'SELECT slug,name,photo_url FROM profiles LIMIT 5;'
```

جدول‌ها:

| جدول | محتوا |
| --- | --- |
| `profiles` | اطلاعات استخراج‌شده و ستون‌های `list_raw_json` و `detail_raw_json` (پاسخ خام) |
| `fields` | تمام فیلدهای کشف‌شده، `source=list/detail`، همراه با `path` و `json_value` |
| `photos` | آدرس، شناسه و مسیر مقصد هر تصویر |
| `scans` | وضعیت لیست‌برداری، `next_offset`، `status`, تعداد صفحات |
| `scan_pages` | Raw JSON هر پاسخ صفحه لیست |

## توقف/ادامه و به‌روزرسانی ماه بعد

- پیشرفت در فواصل `1200` رکورد یا `420` ثانیه در ریپو **Commit و Push** می‌شود.
- در صورت توقف ناگهانی/Cancel، آخرین Checkpoint موفق محفوظ است. **ممکن است کار بعد از آن Checkpoint دوباره درخواست شود**؛ هیچ سیستم مبتنی بر Push دوره‌ای نمی‌تواند ۱۰۰٪ پیشرفت آخرین چند دقیقه قبل از قطع فوری را تضمین کند.
- در اجرای بعد، دیتابیس فشرده بازسازی و لیست ناتمام از `next_offset` ادامه پیدا می‌کند. رکوردهای دارای جزئیات موفق تکرار نمی‌شوند.
- پس از کامل شدن یک لیست، اجرای ماه بعد از ابتدا **فقط صفحات فهرست** را دوباره اسکن می‌کند؛ چون داده تازه می‌تواند در هر صفحه‌ای درج شده باشد. **جزئیات رکوردهای جدید یا تغییرکرده** را می‌گیرد و قبلی‌های بدون تغییر را رد می‌کند.
- هر ماه روز اول به‌صورت خودکار اجرا می‌شود. برای به‌روزرسانی *اجباری* جزئیات قدیمی، ورودی `refresh_days=30` را بده (این کار ترافیک بیشتری تولید می‌کند).
- هر اجرا اگر به محدوده ۳۲۰ دقیقه نزدیک شود با Checkpoint مرتب متوقف می‌شود؛ دوباره `Run workflow` را بزن. طول اجرای GitHub-hosted runner محدودیت دارد.
- از پارامتر `max_details=500` برای اجرای آزمایشی استفاده کن؛ صفر به معنی تمام رکوردهای Pending است.

## اجرای محلی برای تست یا عیب‌یابی

```bash
python3 -m pip install -r requirements.txt
python3 crawler.py sync --max-details 10
python3 crawler.py status
```

اگر API محدودیت سرعت یا خطای 429 بدهد، `max_rps` را کمتر کن؛ گزینه تعداد worker بالا به‌تنهایی نرخ تقاضا را بیشتر نمی‌کند، چون یک Rate Limiter مشترک داریم. لطفاً محدودیت استفاده سایت و الزامات حفاظت داده را رعایت کن و ریپو را Private نگه دار؛ پاسخ‌ها ممکن است شامل داده‌های تماس شخصی باشند.

**توجه:** این بسته حاوی کد است؛ دیتا و URLها پس از اجرای موفق GitHub Actions تولید می‌شوند. محیط فعلی امکان ارتباط مستقیم با `icbar.ir` برای دانلود سراسری ندارد.
